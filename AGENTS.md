# Agent instructions

## Project

SCSSTree is a JavaScript library that extends CSSTree to parse SCSS. Its `scss` export supports SCSS variables, interpolation, placeholder selectors, nested properties, expressions, and SCSS at-rules. The package is ESM and requires Node.js 18.18 or newer.

## Repository layout

- `src/index.js` is the package entry point; `src/scss.js` assembles the syntax extension.
- `src/node/`, `src/atrule/`, and `src/scope/` contain node definitions, at-rule parsers, and value/selector recognizers.
- `src/atrules.js`, `src/tokenize.js`, and `src/types.js` define SCSS at-rules, single-line comment token handling, and lexer types.
- `tests/scss.test.js` contains parser and round-trip tests; `tests/eslint-css.test.js` checks ESLint CSS plugin compatibility; `tests/runtime-dependencies.test.js` guards runtime imports.
- `tests/fixtures/scss.scss` is also parsed by the repository's ESLint configuration.
- `dist/` is generated by the build; do not edit generated output directly.

## Setup and validation

Install dependencies with `npm install`. Useful checks are:

- `npm run build` — type-check JavaScript and emit declarations to `dist/`.
- `npm run test:unit` — run the Mocha unit tests.
- `npm run test:attw` — verify the published package's type exports.
- `npm test` — build and run the test suite, including type-export checks.
- `npm run lint` — lint source and tests; this also exercises SCSS parsing through the fixture.
- `npm run fmt` — format the repository with Prettier.

For parser changes, preserve parse/generate/reparse stability and verify both `fork(scss)` and the ESLint CSS plugin path, which supplies only CSS syntax definition data. Keep `tests/eslint-css.test.js` passing.

## Implementation guidance

- Keep changes focused and follow existing JavaScript and formatting conventions.
- Reuse the token type constants in `src/token-types.js`; avoid adding runtime imports from CSSTree packages outside `src/scss.js`.
- `scss` can receive either the full syntax configuration or only `{ types, atrules, properties }`. Treat fields from the previous syntax as optional so both integration paths continue to work.
- Add or update tests for behavior changes and update `tests/fixtures/scss.scss` when a construct should be covered by fixture linting.

## Commits and pull requests

Commit messages and pull request titles **MUST** use Conventional Commits format: `type(scope): description` (scope is optional). Choose an appropriate type and, when useful, a repository-specific scope; for example, `fix(parser): handle nested SCSS properties` or `docs: clarify parser integration`.
